How embeddings work

Text becomes a location in a high-dimensional map of meaning.

Amazon Titan Text Embeddings v2 converts every passage—and each incoming query—into a normalized vector with 1,024 numbers.

  • Similar meaning tends toward nearby coordinates
  • Different wording can still be close
  • It retrieves text; it does not generate an answer
ocean ↕ landtemperature → sea surface temperature ocean thermal anomaly query soil moisture

Elasticsearch vector index

Approximate nearest neighbors, ranked by cosine similarity.

"embedding": {
  "type": "dense_vector",
  "dims": 1024,
  "index": true,
  "similarity": "cosine"
}
  • Query vector: embed the user’s text with the same model
  • Candidate search: inspect 200 approximate neighbors
  • Top passages: retain the closest 50
  • Collection result: deduplicate passage hits by collection ID

Three retrieval modes

Exact language and conceptual similarity are complementary.

Keyword

Lexical search

Multi-field text match. Boosts short name, title, variable name, science keywords, and instruments. Best for exact identifiers and terminology.

Semantic

Vector search

Nearest passages in embedding space. Best when intent matches but vocabulary differs.

Default

Hybrid search

Runs both searches, deduplicates each list by collection, then combines their ranks with reciprocal-rank fusion.

Reciprocal-rank fusion

Reward agreement without comparing incompatible scores.

score(c) = Σ 1 / (60 + ranksource(c))

Lexical list

BM25-style relevance scores are converted to ranks.

Semantic list

Cosine-based vector scores are converted to ranks.

Fused list

Collections appearing near the top of either—or both—rise in the final order.

Evidence records preserve which passage and retrieval source contributed to the result.
